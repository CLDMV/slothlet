# Slothlet v3.23.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 3.23.0 is mostly a fix release. Its headline change makes the module ownership rule hold everywhere a module can reach while the permission system is on: module code may change data only under the api path it owns, whether it writes at the top of `self`, several levels down, through a node another module handed it, through `api.add` and `api.remove`, or through the framework's own setters. Write permissions join the permission system as `:write` rules, so the host or a manifest can grant one module writes into another's subtree, and a module removed from the api keeps no standing for the code it left behind.

The one new feature is the permission system's three modes (`permissions.mode`): `"on"`, `"off"` (the default with no `permissions` config), and `"disabled"`. Off, no rule is evaluated and ownership refuses nothing, but module code still cannot change the framework's own `slothlet` namespace, root functions, or the framework's keys on api nodes. Only `"disabled"` leaves those open.

The rest of the release fixes how the api composes and behaves: eager and lazy mode now compose the same api, and a structure check compares them. Writes through an array api member reach the array, and frozen nodes keep their permission checks. Live-runtime callers are attributed correctly across overlapping calls and instances. The browser no longer needs `setImmediate`. Members named like `name`, `length` or `then` behave as members. A synchronous `around` hook may return a thenable derived from `next()`. The EventEmitter tracking that held every emitter a module listened to until shutdown now holds them weakly, so connections a module opens are collectable again.

Every dependency change is dev-only. `dependencies`, `optionalDependencies`, `peerDependencies` and `engines` are unchanged. Several fixes refuse things that used to be allowed or silently misbehaved; see Behavior changes and Upgrade notes.

## ✨ Features

### Permission modes: on, off, disabled ([#628](https://github.com/CLDMV/slothlet/pull/628))

`permissions.mode` sets how much of the permission system applies:

| Mode         | How                                                                              | What applies                                                                                                            |
| ------------ | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `"on"`       | a `permissions` config (the default for one), or `control.enable()`              | Every rule: calls, reads, writes, and ownership.                                                                        |
| `"off"`      | no `permissions` config, `mode: "off"`, `enabled: false`, or `control.disable()` | Module code cannot change the framework's own namespace, root functions, or keys on api nodes. Nothing else is checked. |
| `"disabled"` | `mode: "disabled"` in the config                                                 | Nothing, apart from the reserved names `slothlet`, `shutdown` and `destroy` on `self`.                                  |

`enabled: true` and `enabled: false` keep working as `"on"` and `"off"`. `api.slothlet.permissions.control.mode` reports the mode, and a mode the host switched to with `control.enable()` / `control.disable()` now holds across `reload()`. See [docs/PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#modes).

## ⚠️ Behavior changes

These are fixes, but code that relied on the old behavior will notice them.

- **The framework's own namespace is kept from module code by default** ([#628](https://github.com/CLDMV/slothlet/pull/628)). With no `permissions` config (mode `"off"`), module code that assigns, defines, or deletes anything under `self.slothlet`, replaces `self.shutdown` / `self.destroy`, or changes a framework key on a node (`__mode`, `____slothletInternal`, …) now gets `PERMISSION_DENIED`. Calls into the namespace behave as before. Set `permissions: { mode: "disabled" }` to leave it open.
- **Module code is held to its own api path at any depth while the permission system is on** ([#628](https://github.com/CLDMV/slothlet/pull/628)). A write into another module's subtree through a nested `self` path or through a node another module returned now throws `LOOSE_SET_NOT_OWNED` (or `PERMISSION_DENIED` from a write rule). With the system off, ownership refuses nothing. Grant cross-module writes with a `:write` rule (see below).
- **`api.add`, `api.remove`, `api.reload`, and the metadata and versioning setters are writes when module code calls them** ([#628](https://github.com/CLDMV/slothlet/pull/628)). Module code mounts, removes and reloads only under its own path, cannot reuse another live module's `moduleID`, and cannot mount at a path where a module it mounted is still mounted.
- **Rules module code registers are limited to its own subtree** ([#628](https://github.com/CLDMV/slothlet/pull/628)). `self.slothlet.permissions.addRule`, a manifest mounted by module code, the `permissions` option of a module's `api.add`, and `self.slothlet.event.rules.add` accept only targets inside the module's own subtree. To let a module manage rules beyond it, grant it `slothlet.permissions.addRule`. A Proxy anywhere in a rule's condition is refused.
- **A removed module's code has no standing** ([#628](https://github.com/CLDMV/slothlet/pull/628)). Functions it kept or handed out own nothing. With permissions on, their calls are refused, and they cannot reach `self.slothlet.*`. Its hooks, lifecycle subscribers, event listeners, rule conditions and event strategy stop. This holds even after another module is mounted under the same `moduleID`.
- **Another module's data objects are read-only views unless it may write them** ([#628](https://github.com/CLDMV/slothlet/pull/628)). A `Map`, `Set`, `Date`, buffer, typed array, `RegExp`, `Promise` or `WeakRef` read through `self` from another module's path is a live view that refuses changes. Native code such as `fs.write`, `crypto` or `structuredClone` rejects a view, so copy first (`Buffer.from(view)`, `view.slice()`). The owner, the host and a module granted the write get the object itself.
- **`metadata.getFor`, `metadata.getForVersion`, `versioning.getVersionMetadata` and `versioning.list` return copies** ([#628](https://github.com/CLDMV/slothlet/pull/628)). Changing what they return no longer changes the stored data.
- **A callable `then` is refused where slothlet would await it** ([#580](https://github.com/CLDMV/slothlet/pull/580)). A file or folder named `then` gives `MODULE_THENABLE_NAME`. A module value with a callable `then` becoming an api node gives `MODULE_THENABLE_EXPORT`. Assigning one onto a node gives `API_MEMBER_THEN_RESERVED`, and an `api.add` path or version tag segment named `then` is refused. Data named `then` (`if`/`then`/`else` schemas, `then: 1`) still reads back.
- **Reserved folder names and `__proto__` exports are refused** ([#580](https://github.com/CLDMV/slothlet/pull/580), [#585](https://github.com/CLDMV/slothlet/pull/585)). A folder named like a framework-internal key fails with `MODULE_RESERVED_DIRNAME`, and an export named `__proto__` is refused. A module's own `_x` or `__priv` exports are now kept in lazy mode, as eager mode always did.
- **`addapi.mjs` composes as the file named after its level** ([#585](https://github.com/CLDMV/slothlet/pull/585)), at initial load as well as on `api.add`. Its default becomes the node, with named exports beside it, instead of being merged flat.
- **In lazy mode, a folder whose only entry is a same-named folder stays nested** ([#582](https://github.com/CLDMV/slothlet/pull/582)), as in eager mode. `api/x/foo/foo/get.mjs` is `api.x.foo.foo.get()` in both modes; the old lazy path `api.x.foo.get()` is gone.
- **Hook handlers are called with no `this`** ([#628](https://github.com/CLDMV/slothlet/pull/628)). A handler used to be called as a method of its own registration; it is now a plain function call, as a lifecycle subscriber's is.
- **Third-party emitters keep their listeners when the last instance shuts down** ([#606](https://github.com/CLDMV/slothlet/pull/606)). Each listener is restored to the function the code registered, instead of being stripped.

## 🐛 Bug Fixes

### Module ownership and write permissions ([#628](https://github.com/CLDMV/slothlet/pull/628))

The ownership rule (a module mounted at `P` writes only under `P.*`) used to be checked only for a write at the top of `self`, permissions or not. It now covers every route module code has to another module's data, and it refuses writes while the permission system is on; with it off, ownership is still recorded but refuses nothing. Fixes [#625](https://github.com/CLDMV/slothlet/issues/625).

- **Writes at any depth, judged by what they reach.** Assignment, definition, deletion, prototype changes, `preventExtensions`, `freeze` and `seal` through any node read from `self` are judged at the path of the node they actually reach, including through a node or value another module stored or returned. A getter or a module-stored Proxy on the way is not walked through, and version dispatchers are followed to the versioned node. This also covers a write through a lazy node that has not loaded yet.
- **The framework's surface is protected.** `self.slothlet.*`, the root functions (`shutdown`, `destroy`) and the framework-internal keys of every node cannot be changed by module code, however the module reached them, in modes `"on"` and `"off"`. Built-in `:write` rules carry this protection, and the host can lift them for a named caller. `slothlet`, `shutdown` and `destroy` are refused on `self` when defined or deleted, as when assigned, in every mode.
- **`:write` permission rules.** A rule target with the `:write` suffix (`{ caller: "reports.**", target: "cache.**:write", effect: "allow" }`) grants or refuses writes. An allow lets the named callers write another module's subtree, and a deny refuses a write the module would otherwise own. `defaultPolicy: "allow"` grants nothing. Write rules are evaluated while the permission system is on; with it off, only the built-in ones are. See [docs/PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#write-permissions).
- **Rule integrity.** Rules are stored as frozen copies, so editing the object afterwards changes nothing. Module code adds and removes rules only for its own subtree unless granted. A function condition or principal `key`/`resolve` a module registers runs as that module, not as the caller being checked. A removed module's call, write and event rules go with it, and manifest rules survive a full reload.
- **Module lifetime.** Each mount gets its own identity, so code from a removed module stays without standing when another module takes the freed `moduleID`. A module still hears the lifecycle events of its own removal.
- **Data objects and getters.** Another module's `Map`, `Set`, `Date`, buffer, typed array, `RegExp`, `Promise` or `WeakRef` is handed out as a live, read-only view unless the reader may write it. Read rules still decide whether it can be reached at all. The metadata and versioning getters return copies.
- **Events.** A module's event strategy runs as that module, and an event a strategy held back reaches only the listener it was held for.
- **Cross-instance calls.** A module of one instance calling into another instance's api is held to that instance's rules by its path.

### Kept nodes in the live runtime answer as in the async runtime ([#661](https://github.com/CLDMV/slothlet/issues/661), [#666](https://github.com/CLDMV/slothlet/pull/666))

In the live runtime, a node a module kept and uses later from a timer or callback now reads, lists, serializes and answers `in` as it does in the async runtime, frozen arrays included. Code no suspended call accounts for answers for the kept node's reader, and a tie between suspended calls is still refused.

### Eager and lazy compose the same api ([#585](https://github.com/CLDMV/slothlet/pull/585))

The structure check used to compare lazy with lazy. It now loads every lazy node and compares the whole composed shape in both modes, and the divergences it exposed are fixed (Fixes [#583](https://github.com/CLDMV/slothlet/issues/583), [#584](https://github.com/CLDMV/slothlet/issues/584), [#586](https://github.com/CLDMV/slothlet/issues/586)–[#590](https://github.com/CLDMV/slothlet/issues/590), [#594](https://github.com/CLDMV/slothlet/issues/594)):

- `collision: { initial: "merge-replace" }` gives a root file's callable precedence over a same-named folder's.
- In lazy mode, a root file's callable is given to a same-named folder that has none.
- A module's named exports no longer overwrite members of its object default, and the default object itself is never written.
- `api.slothlet.materialize.get()` no longer reports more than 100% or a negative remaining count, and `materialize.wait()` resolves, also after an `api.add` following full materialization.
- Class-instance and object defaults keep their getters live and their prototype methods working, in both modes.

The default-shape rules are documented in [docs/MODULE-STRUCTURE.md](https://github.com/CLDMV/slothlet/blob/master/docs/MODULE-STRUCTURE.md).

### Writes through an array api member reach the array ([#603](https://github.com/CLDMV/slothlet/pull/603), [#656](https://github.com/CLDMV/slothlet/pull/656))

`this.items.push(9)` inside a module method, or any write, definition or deletion through an array api member, now changes the array itself, as in plain JavaScript (Fixes [#602](https://github.com/CLDMV/slothlet/issues/602)). Freezing or sealing a namespace or array node keeps its permission checks (Fixes [#609](https://github.com/CLDMV/slothlet/issues/609)), and a frozen array of objects reads normally through `self` with permissions on (Fixes [#655](https://github.com/CLDMV/slothlet/issues/655)). The limits of frozen and sealed nodes are documented in [docs/PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md).

### Live-runtime caller attribution ([#601](https://github.com/CLDMV/slothlet/pull/601), [#622](https://github.com/CLDMV/slothlet/pull/622))

These fixes apply to `runtime: "live"` and to the browser. The async runtime is unchanged.

- `metadata.caller()` and `lockCaller` agree with permission enforcement when calls settle out of order (Fixes [#591](https://github.com/CLDMV/slothlet/issues/591)).
- With two instances in one realm, `self` resolves against its own instance after an `await` (Fixes [#592](https://github.com/CLDMV/slothlet/issues/592)).
- Code started from an unpatched boundary is never attributed to an unrelated suspended call: host callbacks run as the host, and an unknown boundary fails closed (Fixes [#595](https://github.com/CLDMV/slothlet/issues/595)).
- `scheduler.postTask`, promise reactions, every `on*` handler of the global's `EventTarget` interfaces, `PerformanceObserver` and `ReportingObserver` are now patched boundaries.
- In the browser, each instance and mount loads its own copy of each leaf (Fixes [#598](https://github.com/CLDMV/slothlet/issues/598)), and two mounts of one folder are told apart by the copy of the leaf each runs.

### Members named like node properties ([#580](https://github.com/CLDMV/slothlet/pull/580), [#623](https://github.com/CLDMV/slothlet/pull/623))

A file, folder, export or mount named `name`, `length`, `prototype`, `toString`, `valueOf`, `toJSON` or `constructor` is an ordinary member and wins over the node's own answer. `session/name/set.mjs` is `api.session.name.set()` in both modes, where eager mode used to crash and lazy mode returned `undefined` (Fixes [#571](https://github.com/CLDMV/slothlet/issues/571)). A lazy partial reload keeps a folder's member names (Fixes [#593](https://github.com/CLDMV/slothlet/issues/593)). In the browser, a Proxy default that answers `then` from its trap is refused like any other thenable.

### Browser: no `setImmediate` needed ([#579](https://github.com/CLDMV/slothlet/pull/579))

The browser build and Electron context-isolated renderers have no `setImmediate`, which made every composed function leaf log a lifecycle warning and left the routine stack unpatched. Deferred work now uses `setImmediate` where present, then `MessageChannel`, then `setTimeout` (Fixes [#578](https://github.com/CLDMV/slothlet/issues/578)). `SlothletWarning` now keeps and prints a `cause`, and a lifecycle handler failure for an `impl:*` event names its api path and module.

### Synchronous `around` hooks may derive from `next()` ([#608](https://github.com/CLDMV/slothlet/pull/608))

A synchronous `around` hook that calls `next()` and gets a thenable may return any thenable, such as `next().then(check)`, instead of being refused with `HOOK_AROUND_RETURNED_PROMISE` (Fixes [#607](https://github.com/CLDMV/slothlet/issues/607)). A rejection of the derived thenable reaches the error hooks. Returning a thenable without calling `next()` is still refused. See [docs/HOOKS.md](https://github.com/CLDMV/slothlet/blob/master/docs/HOOKS.md).

### Emitters a module listens to are collectable ([#634](https://github.com/CLDMV/slothlet/pull/634), [#606](https://github.com/CLDMV/slothlet/pull/606))

Slothlet kept every EventEmitter that received a listener inside an api context in a strong set until the last instance shut down, so sockets and `fetch` connections opened from a module were never collected (Fixes [#611](https://github.com/CLDMV/slothlet/issues/611)). The set now holds weak references, so emitters the application releases are collectable. Separately, the last shutdown no longer strips listeners from third-party emitters: an open socket with no `error` listener could crash the process later (Fixes [#605](https://github.com/CLDMV/slothlet/issues/605)).

## Upgrade notes

- **No API was removed.** Most applications upgrade without changes. Check the Behavior changes above if your modules write into each other's data, register permission rules, read another module's `Map`/`Set`/`Date`/buffer and pass it to native code, rely on a member or file named `then`, or relied on the old lazy flattening of a `foo/foo/` folder.
- **Modules that change the framework namespace:** with no `permissions` config, module code that writes into `self.slothlet`, replaces `self.shutdown` / `self.destroy`, or changes a framework key on a node is now refused. Move that into host code, or set `permissions: { mode: "disabled" }`.
- **Cross-module writes:** if one module legitimately writes into another's subtree, grant it with a rule, for example `{ caller: "reports.**", target: "cache.**:write", effect: "allow" }`, in the host's `permissions.rules` or the owning module's manifest.
- **Module-registered rules beyond the module's own subtree:** grant the module `slothlet.permissions.addRule` (`{ caller: "admin.**", target: "slothlet.permissions.addRule", effect: "allow" }`).
- **Data objects passed to native code:** copy what another module holds before handing it to `fs`, `crypto`, a socket or `structuredClone`, or grant the reader the write so it gets the object itself.
- **Live runtime:** callbacks started from unpatched boundaries now run as the host, not as whichever call was suspended. Wrap a callback that must keep a module's identity with `self.slothlet.lockCaller`.
