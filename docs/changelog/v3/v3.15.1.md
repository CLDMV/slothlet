# Slothlet v3.15.1 Changelog

**Release Date**: August 2026
**Release Type**: Patch
**Branch**: `release/3.15.1`

---

## Overview

Version 3.15.1 is a **maintenance and supply-chain-hardening release — no runtime code changed**. The public API, loader behavior, and every runtime surface are identical to 3.15.0. This release is entirely CI/release-pipeline hardening, a dev-toolchain security bump, and documentation fixes.

The substantive change is **least-privilege GitHub Actions token permissions** across the workflow set, alongside clearing two high-severity advisories in the **dev-only** test/lint toolchain. An OpenSSF Scorecard badge now surfaces the repository's supply-chain posture in the README.

---

## 🔒 Security & supply chain

### Least-privilege workflow token permissions (#319)

Every GitHub Actions workflow now declares a read-only top-level `permissions: { contents: read }` default, with write scopes narrowed to the single job that needs them rather than granted workflow-wide. This satisfies OpenSSF Scorecard's Token-Permissions check and shrinks the blast radius of a compromised action. Behavior is unchanged — each job still receives exactly the permissions it had before, only scoped to the job instead of the whole workflow.

### Dev-toolchain advisories cleared (#322)

Two high-severity denial-of-service advisories were resolved by bumping **dev-only, transitive** dependencies:

- `brace-expansion` 5.0.7 → **5.0.9** (via `eslint` → `minimatch`) — GHSA-mh99-v99m-4gvg, GHSA-rgw5-rvv9-x895.
- `nanoid` 3.3.16 → **3.3.18** (via `vitest` → `vite` → `postcss`) — GHSA-2v37-7h3g-55p8.

Both live purely in the test/lint toolchain and are **never reachable from the published package**, which remains dependency-free at runtime — consumers were never exposed. `npm audit` now reports **0 vulnerabilities**.

## 🔧 CI & tooling

- **feature-PR auto-opener now triggers on `deps/**` branches (#321)** — the reusable workflow already mapped `deps/*`, but this repo's caller trigger omitted it, so `deps/*` branches never auto-opened a PR. The trigger list is realigned with the reusable and the branch-naming convention.
- **Accurate changelog contributor lists (#314)** — `BOT_NAME` / `BOT_EMAIL` are now passed to the v4 release / feature-PR workflows.
- Two workflow files that had drifted to 2-space indentation were normalized to the fleet's 4-space YAML convention (semantically identical).
