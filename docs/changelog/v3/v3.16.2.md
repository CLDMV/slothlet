# Slothlet v3.16.2 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/3.16.2`

---

## Overview

Version 3.16.2 fixes a real gap in the stackable routines shipped in v3.16.0: a routine's **root cascade** ran its contributors with no active instance extent, so any contributor reaching ambient `self.*` threw — while the identical contribution invoked per-path resolved fine. It also repairs the post-release **docs-site build** (failing since v3.16.0 on an unparseable JSDoc type) and refreshes the contributor guide. The routine-cascade fix is the one runtime change; it is a drop-in for v3.16.1.

---

## 🐛 Bug Fixes

### Routine cascades run each contributor in its own extent (#394)

The stackable routines introduced in v3.16.0 expose a callable at each contribution's composed path (`api.<path>.<name>()`) and a **root cascade** (`api.<name>()` / `api.slothlet.<name>()`, plus the auto-fired `startup` / `shutdown` / `destroy` paths). A per-path call is dispatched through the wrapped api node, which enters the instance extent before invoking the contribution — so ambient `self.*` inside a routine body resolves. The root cascade, by contrast, was a plain callable that invoked each contributor's raw implementation with **no active extent**: a contributor whose body reached `self.*` threw `RUNTIME_NO_ACTIVE_CONTEXT_SELF` (surfaced as a `ROUTINE_FAILED` cascade failure), even though the same contribution called per-path worked. That asymmetry made `await api.slothlet.initialize()` / `await api.initialize()` unusable for any contributor that reached `self.*`, forcing callers to wrap the cascade in `api.slothlet.run(...)` by hand.

The routine executor now runs **every** contributor — cascade and per-path alike — inside the instance extent via the same `contextManager.runInContext` primitive a wrapped leaf uses, attributed to that contributor's **own** leaf wrapper. Each contribution therefore runs exactly as if it had been called directly: its `self.*` resolves, and its permission/caller identity is the contributor itself rather than a shared slot or instance identity. A routine now purely fans a call out to every matching contribution without altering the semantics of any one of them; per-contributor error attribution — and thus cascade failure aggregation — is unchanged.

### Docs build no longer fails on the `#assignWithRoutineRevert` JSDoc type (#385)

The `@param` type for `ModesProcessor#assignWithRoutineRevert`'s `assign` callback was written as a TypeScript arrow-function type with a function-typed parameter (`(registerWrapper: (wrapper: object) => void) => …`). `tsc` accepts that — so declaration generation passed — but `jsdoc2md`'s type parser rejects a function-typed parameter inside an arrow type, so `docs:build` exited non-zero. That surfaced only at the post-release **"Publish Docs"** step (the docs build doesn't run on feature PRs), which failed on v3.16.0 and v3.16.1. It affected the docs site only; the npm package publish is a separate workflow and shipped normally both times.

The type is now expressed as proper `@callback` typedefs (`AssignCandidate` + `RegisterWrapper`), which parse under both `jsdoc2md` and `tsc` while keeping the named `registerWrapper`/`wrapper` parameters. Because the method is private, there is no change to any public type declaration.

## 📚 Documentation

### Contributor guide refreshed for the v4 flow (#386)

`CONTRIBUTING.md` had drifted. It told contributors to branch from `master` (the flow branches from `next`) and to globally `export NODE_OPTIONS=--conditions=slothlet-dev` / `NODE_ENV=development` during setup — the latter is actively harmful, because a global `slothlet-dev` condition forces source-mode resolution onto every process and breaks the dist-mode / post-build test paths (the test config even strips an inherited one). The guide now:

- Drops the environment-export setup step and shows the per-command `node --conditions=slothlet-dev <script>` form for one-off source runs instead.
- Documents the v4 staging flow: branch from `next` with a conventional prefix, PRs target `next`, releases ship via `next → master`.
- Adds the `*.test.vitest.mjs` test-file convention, the `npm run vitest -- <pattern>` subset passthrough, the `npm run coverage` gate, and the lint/format precommit hook.

## Upgrade notes

- No breaking changes — drop-in for v3.16.1. The one runtime change is the routine-cascade fix (#394): a root-cascade routine (`api.<name>()` / `api.slothlet.<name>()`) or an auto-fired `startup` / `shutdown` / `destroy` routine whose contributor bodies use ambient `self.*` now works without wrapping the call in `api.slothlet.run(...)`. Per-path routine calls are unaffected, and any existing `api.slothlet.run(...)` wrap around a cascade stays correct — it simply becomes optional.
