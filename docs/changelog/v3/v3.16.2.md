# Slothlet v3.16.2 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/3.16.2`

---

## Overview

Version 3.16.2 is a documentation-and-tooling patch. It repairs the post-release **docs-site build**, which had been failing since v3.16.0 because one JSDoc `@param` type couldn't be parsed by the docs generator, and refreshes the contributor guide. No runtime code changed — this is a drop-in for v3.16.1.

---

## 🐛 Bug Fixes

### Docs build no longer fails on the `#assignWithRoutineRevert` JSDoc type (#385)

The `@param` type for `ModesProcessor#assignWithRoutineRevert`'s `assign` callback was written as a TypeScript arrow-function type with a function-typed parameter (`(registerWrapper: (wrapper: object) => void) => …`). `tsc` accepts that — so declaration generation passed — but `jsdoc2md`'s type parser rejects a function-typed parameter inside an arrow type, so `docs:build` exited non-zero. That surfaced only at the post-release **"Publish Docs"** step (the docs build doesn't run on feature PRs), which failed on v3.16.0 and v3.16.1. It affected the docs site only; the npm package publish is a separate workflow and shipped normally both times.

The type is now expressed as proper `@callback` typedefs (`AssignCandidate` + `RegisterWrapper`), which parse under both `jsdoc2md` and `tsc` while keeping the named `registerWrapper`/`wrapper` parameters. Because the method is private, there is no change to any public type declaration.

## 📚 Documentation

### Contributor guide refreshed for the v4 flow (#386)

`CONTRIBUTING.md` had drifted. It told contributors to branch from `master` (the flow branches from `next`) and to globally `export NODE_OPTIONS=--conditions=slothlet-dev` / `NODE_ENV=development` during setup — the latter is actively harmful, because a global `slothlet-dev` condition forces source-mode resolution onto every process and breaks the dist-mode / post-build test paths (the test config even strips an inherited one). The guide now:

- Drops the environment-export setup step and shows the per-command `node --conditions=slothlet-dev <script>` form for one-off source runs instead.
- Documents the v4 staging flow: branch from `next` with a conventional prefix, PRs target `next`, releases ship via `next → master`.
- Adds the `*.test.vitest.mjs` test-file convention, the `npm run vitest -- <pattern>` subset passthrough, the `npm run coverage` gate, and the lint/format precommit hook.
