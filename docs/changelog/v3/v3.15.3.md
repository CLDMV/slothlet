# Slothlet v3.15.3 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/3.15.3`

---

## Overview

Version 3.15.3 is a **bug-fix release for the wrap-on-set / `api.add()` materialization path and the hook lifecycle's default handling**. The headline fix replaces eager, static-snapshot materialization of assigned or mounted objects with live Proxy delegation, so `self.X = obj` and `api.slothlet.api.add()` both give a genuinely live, two-way view onto the underlying object instead of a frozen copy — including for `EventEmitter`-derived values and other native handles, which previously had to be excluded outright. The second fix consolidates several hand-typed default literals (`apiDepth`, the hook-subset default) into single named constants and corrects a hook-subset default that used `||` instead of `??`, which silently replaced a caller's intentionally empty hook subset with the default.

No public API changed and there are no breaking changes; this is a drop-in for 3.15.2. Coverage remains at 100% with regression tests for both fixes.

---

## 🐛 Bug Fixes

### Wrap-on-set and `api.add()` use live Proxy delegation instead of eager materialization (#340, #342)

`___createChildWrapper` / `___adoptImplChildren` / `setTrap` (`src/lib/handlers/unified-wrapper.mjs`) implemented wrap-on-set and child adoption as eager materialization: an assigned value was structurally cloned, its children walked once and captured as static, non-writable snapshots, and the snapshot fields deleted off the source object afterward. Only arrays were special-cased to expose the real object transparently through the Proxy's `getPrototypeOf`/`constructor` handling — everything else, including a plain object assigned via `self.X = obj`, got a disconnected copy. That one design produced two previously-filed symptoms: `self.X = obj` never reflected live changes in either direction (contradicting `docs/CONTEXT-PROPAGATION.md`'s claim that wrap-on-set uses "the same wrapper construction `api.slothlet.api.add()` uses"), and `EventEmitter`-derived values (including trivial application subclasses never at risk of the real hang) were excluded from wrapping entirely as a blanket workaround for a hang whose actual cause was a missing cycle guard, not `EventEmitter`-ness. Ten targeted changes in `unified-wrapper.mjs` replace the clone-and-snapshot mechanism with live pass-through: the constructor and child-wrapper path no longer clone the impl; a primitive child gets a live forwarding accessor instead of a static value; the Proxy target, `getPrototypeOf` trap, and `constructor` getter generalize the array-only "use the real object" treatment to any object impl; `setTrap` invokes an existing live accessor directly (via `Reflect.set`) instead of deleting and redefining a static value; and `applyTrap` substitutes the real object for `thisArg` when a wrapper proxy would otherwise be passed to a native method that depends on internal slots tied to exact object identity (e.g. a `net.Socket`'s stream internals) — the change that makes calling a wrapped native method actually work, not merely avoid hanging. Named children still decompose into individually self-bound, individually permission-gated leaves exactly as before; only the delivery mechanism changed, from a frozen snapshot to a live reference. `null` is treated as a terminal value throughout the deferred-child live-forwarding path rather than being treated as an object to descend into. Fixed in #342 (root-caused and unified in #340, which supersedes the two earlier reports it consolidates).

### Hook-lifecycle default literals consolidated; empty hook subset no longer silently replaced (#343, #344)

`apiDepth`/`maxDepth` and the hook-subset default (`"primary"`) were each hand-typed as bare literals at multiple call sites with no shared constant — `config.mjs`'s `apiDepth` normalizer and three separate `Infinity` parameter defaults in `eager.mjs`, `lazy.mjs`, and `loader.mjs`; the hook-manager's `"primary"` fallback and four separate re-typed `["before", "primary", "after"]` iteration arrays. Each set is now a single named, frozen constant that every call site reads, removing the silent-drift hazard of one site's literal changing without the others following. While consolidating the hook-subset default, `options.subset || "primary"` was also corrected to `options.subset ?? "primary"` — the `||` form silently replaced a caller's deliberately empty subset (`[]`, an empty but valid falsy value) with the full default subset instead of respecting it. Fixed in #344 (from #343).

## Upgrade notes

- **No breaking changes — drop-in for 3.15.2.** No runtime code changes are required. If your code previously worked around the wrap-on-set / `add()` materialization gap — reassigning through the raw object instead of the wrapped `self.X`, or avoiding wrap-on-set for `EventEmitter`-derived values — those workarounds are no longer necessary, though they remain harmless.
- If any caller relied on an empty hook subset silently falling back to the full default (the `||` bug fixed in #344), it now runs with the empty subset as passed — this restores the documented behavior and only changes callers that were unintentionally depending on the bug.
