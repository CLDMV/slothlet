# Slothlet v3.13.2 Changelog

**Release Date**: August 2026
**Release Type**: Patch
**Branch**: `release/3.13.2`

---

## Overview

Version 3.13.2 fixes a composition regression introduced in 3.13.0 (#283, #287) that broke permissions-enabled consumers using version dispatch. The module-private rule shipped in 3.13.0 (#269) makes an `_`/`__`-prefixed member private to its module and denies it to an unidentified (host) caller by default. slothlet's OWN reserved marker keys — `__isVersionDispatcher` and `__logicalPath` — are `__`-prefixed, and the framework reads them internally in several places to recognize a version dispatcher. Under any `permissions` block those internal reads were treated as host reads of a private member and denied, so composing a version-dispatched field — or merely mounting an extension whose manifest carried an ordinary array field — threw `PERMISSION_DENIED` at a `…__isVersionDispatcher` path and every extension failed to activate. 3.12.3, which predates #269, composed the same tree fine; a permissions-enabled consumer could not upgrade past it.

The fix keys entirely on object identity — a module-private brand marking the dispatchers slothlet itself creates — never on the key name. A consumer can legitimately export a member named `__isVersionDispatcher` (it is not a #260-reserved name), so a name-based exemption would hand the host that member and reopen exactly what #269 closed. Two independent framework read paths carried the fault and are both corrected. No public API changed; there are no breaking changes.

## 🐛 Bug Fixes

### Version-dispatcher markers denied by the module-private host gate (#283, #287)

The regression had two independent read paths, fixed in PR #284 and PR #288.

**The merge-time confirm read (#283 / PR #284).** When a version-dispatched field collides with an existing module, composition merges the dispatcher into that module's wrapper — copying the dispatcher's marker keys onto it — and then reads `__isVersionDispatcher` back to confirm the field is a dispatcher. That read carries no caller identity (the framework itself, mid-composition), so under the secure-default `private.host: deny` it was refused. A module-private `WeakSet` now brands the objects slothlet creates and stamps with a marker (a dispatcher's proxy and target, and any wrapper a dispatcher merges into); the permission read gate exempts a read of one of the reserved marker keys ONLY when the carrying object is branded, so slothlet's own marker stays readable while a consumer's identically-named member stays denied.

**The detection-walk probe (#287 / PR #288).** The deeper, more general fault: the framework's tree walks (`collectPendingMaterializations` during `api.add`, plus the shutdown-drain and hook-collect walks) skip version dispatchers, and they identified one by READING `obj.__isVersionDispatcher` on every node visited. That read is itself a `__`-private access, so under `private.host: deny` the walk's own probe was denied on ANY gated data leaf — including a plain `manifest.activationEvents` array, with nothing version-dispatched at all. The marker was doing double duty: the "is this a dispatcher?" signal AND a gated `__`-private property. Detection now uses the module-private brand — `isFrameworkInternal(obj)`, a `WeakSet` identity check that reads no property and never engages the gate. A real dispatcher is branded and skipped exactly as before; a plain data leaf is not branded, is correctly "not a dispatcher," and is walked without any gated probe.

A data field may legitimately hold different data in one version than another, so a version-dispatched data point (e.g. `activationEvents` varying per version) is a valid target — and now composes under permissions and resolves its own per-version data, as does an ordinary un-dispatched field.

## 🧪 Tests

New regression suites accompany both fixes:

- **Merge path (#284):** the collision-merge marker read under a gated tree, a scope guard that a genuine consumer `__`-private member stays denied to the host (#269 intact), and a unit test for the brand registry.
- **Detection walk (#288):** mounting an extension whose `manifest.activationEvents` is a plain array under `defaultPolicy: "deny"` no longer denies the walk's probe; the declared leaf stays reachable and the array intact; a version-dispatched `activationEvents` carrying different data per version composes under `deny` and resolves each version's own data; and a dispatcher the walk descends through is skipped by the brand rather than probed.

Both suites run across eager and lazy modes; the full test suite passes.

## Upgrade notes

- **No breaking changes.** The fix restores composition that 3.12.3 supported and narrows an over-broad denial introduced in 3.13.0; #269's rule — the host and foreign modules cannot read a module's `_`/`__`-private members — is unchanged, and a consumer's own `__`-prefixed data member stays private.
- **Recommended for any permissions-enabled application that version-dispatches fields or mounts extensions with manifests.** If you deferred the 3.13.0/3.13.1 upgrade because permission-gated composition threw `PERMISSION_DENIED` at a `…__isVersionDispatcher` path, 3.13.2 resolves it with no consumer-side change required.
