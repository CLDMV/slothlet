# Slothlet v3.15.0 Changelog

**Release Date**: August 2026
**Release Type**: Minor
**Branch**: `release/3.15.0`

---

## Overview

Version 3.15.0 hardens and extends slothlet's runtime API-mutation surface (`api.slothlet.api.add()` / `remove()` / `reload()`). The headline change makes a module's **`moduleID` character-safe**: a colon — and now every other character — round-trips through `add` / `leaves` / `remove` / `reload`, closing a silent-corruption bug where an id like `vine:abc` mounted fine but could never be enumerated or removed (#303). Alongside it, `remove()` gains a **surgical scoped form** — `remove(moduleID, apiPath)` — that detaches only the nodes one module owns under a path, and both **scoped removals and synthetic (in-memory) adds now survive `reload()`**.

Two correctness fixes round out the release: `api.add()` now **refuses prototype-polluting mount-path segments** (#302), and reading a built-in function member (`.apply` / `.call` / `.bind`) off a **callable leaf** no longer materializes it as a child endpoint or corrupts the leaf's record (#304).

No public API signature changed and there are no breaking changes; the runtime-mutation surface is a strict superset of 3.14.0's.

## ✨ Features

### Character-safe `moduleID` resolution (#303)

A `moduleID` may now contain **any character** — `:`, `/`, `.`, `-`, everything — and still round-trip through every lifecycle operation. Previously `:` doubled as slothlet's internal `moduleID:apiPath` composite-key separator, so a namespaced id such as `vine:abc` or `plugin:opensearch:v1` was silently unmanageable: `add()` returned the exact id, the leaf resolved, but `leaves(id)` returned `[]` and `remove(id)` / `reload(id)` couldn't find the mount — the ownership index was keyed under a `:`-truncated prefix. A consumer adopting a `vine:` / `plugin:` namespacing convention got mounts that leaked.

The internal composite key now joins with a **reserved multi-character token** (`MODULE_ID_SEPARATOR`, the string `__slothlet_sep__`) instead of `:`, and the raw base id is stored verbatim (`baseModuleID`) rather than recovered by splitting. Because the delimiter is a token no ordinary id contains, `:` — and every other character — is free. The one thing a `moduleID` (or an `apiPath`) may **not** contain is that reserved token itself; `add()` refuses it up front with a named error (`MODULE_ID_RESERVED_SEPARATOR` for a supplied or auto-generated id, `INVALID_CONFIG_API_PATH_INVALID` for an apiPath), and the guards coerce non-string ids so a numeric `moduleID` can't slip past. See [docs/RELOAD.md](../../RELOAD.md#module-ownership-moduleid).

### Scoped removal: `remove(moduleID, apiPath)`

`remove()` gains an optional second argument that removes **only the nodes a single module owns at or under `apiPath`**, leaving other modules — and that same module's other mounts — untouched:

- `remove(apiPath)` — removes the whole subtree at that path, regardless of which module owns each node.
- `remove(moduleID)` — removes every path that module owns, anywhere.
- `remove(moduleID, apiPath)` _(new)_ — the surgical middle ground: removes/reverts only that module's nodes under the path.

It is a recursive per-node detach pinned to one module: a node the module solely owns is deleted; a shared node reverts to the owner it had before; a container is kept while another module still holds descendants under it — so `remove("modA", "shop")` where `modA` owns `shop.a` and `modB` owns `shop.b` drops `shop.a` and leaves both `shop.b` and the `shop` container standing. It never blanket-deletes the path — that stays the job of `remove(apiPath)`. See [docs/RELOAD.md](../../RELOAD.md#apislothletapiremove).

### Scoped removals and synthetic adds survive `reload()`

Full-instance `reload()` replays the operation history, and that replay now faithfully reproduces two operations it previously dropped:

- **Scoped removals** are recorded with their `moduleID` and replayed as the two-argument `remove(moduleID, apiPath)` form (a module's id survives a reload — the `add` op records `options.moduleID` and it is reused on re-add), so a scoped removal stays applied after reload instead of the module reappearing.
- **Synthetic / in-memory adds** (an inline function, an export map, or the `{ exports, … }` shorthand) record their original inline value as the replay source, so `reload()` re-runs the identical synthetic add — a synthetic mount is no longer lost on a base reload, and it stays removable by its `moduleID` afterward.

See [docs/RELOAD.md](../../RELOAD.md#operation-history-and-replay).

## 🐛 Fixes

### `api.add()` refuses prototype-polluting mount-path segments (#302)

A mount path (and any runtime `self.X = …` write) whose segment is `__proto__`, `constructor`, or `prototype` is now refused with a validation error (`INVALID_CONFIG_API_PATH_INVALID` / `LOOSE_SET_RESERVED_KEY`) before it can assign onto the API root's prototype chain. This closes a prototype-pollution vector in `add()` and the self-assign surface, using the same blocked-segment set the metadata and builder layers already enforce.

### Callable leaf built-in members are no longer materialized as endpoints (#304)

Reading a function's built-in members — `.apply`, `.call`, `.bind`, and other non-enumerable own members — off a **callable leaf** no longer routes through the child-wrapper path that materialized them as fake child endpoints and corrupted the leaf's ownership record. Those members now return the function's real values directly, so a leaf that is itself a function behaves like a plain function under member access.

### Additional hardening

- A scoped removal that **empties a module survives a lazy reload** — a materialization race during replay (tearing down a lazy node registered previously-unregistered descendants after the removal's target list was fixed) that intermittently resurrected the removed subtree is closed; the emptied module is also cleared from the ownership endpoint map, so no stale endpoint leaks until the next reload.
- Internal coverage honesty: several `/* v8 ignore */` markers justified as "never in tests" were replaced with reachability-based tests or honest, precisely-scoped ignores (the covered restore path is now exercised, not hidden).

## 🧪 Tests

- **#303** — colon and multi-colon `moduleID`s (`vine:abc`, `plugin:opensearch:v1`) round-trip through `add` / `leaves` / `remove` / `reload`; a control asserts `remove("vine:abc")` does not collide with a registered `vine`; the reserved separator is refused as a supplied id, an auto-generated id (apiPath carries it), a separator-bearing apiPath with a clean id, and a non-string (numeric) id.
- **Scoped removal** — sole-owned subtree removal leaves no orphaned ownership; a shared container keeps the other module's leaf and the container; a shadowed node reverts to its previous owner; a full scoped removal clears the module's ownership endpoint; scoped removal and synthetic adds survive a `reload()` in both eager and lazy modes (a 300-iteration lazy loop guards the materialization race).
- **#302 / #304** — prototype-polluting segments are refused in `add()`; reading a callable leaf's `.apply`/`.call`/`.bind` returns the function's real members without creating child endpoints.
- Full node + browser coverage gate green (100%, all metrics).

## Upgrade notes

- **No breaking changes.** The runtime add/remove/reload surface is a strict superset of 3.14.0. `remove(pathOrModuleId)` and `remove(pathOrModuleId, apiPath)` are both accepted; existing one-argument calls are unchanged.
- **Colon (and any character) is now safe in a `moduleID`.** If you worked around the old bug by switching namespaced ids to hyphens (`vine-abc`) or adding post-remove verification, you can drop the workaround — `vine:abc` now round-trips through `leaves`/`remove`/`reload`. The only reserved token is the internal `__slothlet_sep__`, which a `moduleID` or `apiPath` may not contain.
- **`add()` is stricter about mount paths.** Paths whose segment is `__proto__`/`constructor`/`prototype`, or which contain the reserved separator, are now rejected with a validation error rather than silently mounting. Legitimate paths are unaffected.
- **Scoped removals and synthetic adds now persist across a base `reload()`.** If you relied on the old behavior where a scoped removal was undone (or a synthetic add was dropped) by `reload()`, note that both are now faithfully replayed.
