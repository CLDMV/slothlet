# Slothlet v3.24.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 3.24.0 finishes the identity half of the permission work that 3.23.0 started. 3.23.0 made the ownership rule hold wherever module code can write; 3.24.0 makes sure the code being checked is attributed to the module that actually wrote it. Code a caller hands to a leaf (a callback, a getter, a `toString`, a Proxy trap) now runs as the caller, with the leaf it runs inside as its ceiling, and code a module hands out (closures, factories, classes and their instances, iterators, accessors) runs as the module that made it, wherever it is called from later. Frames are placed by the file and the script that run them, so code compiled under another file's name is not that file's.

The rest of the release is fixes: `new` on a lazy folder that has not loaded yet now constructs the class, reading a cyclic object through `self` inside a module closes the cycle again, and the repository's development tooling moves to Node 22.22 while the runtime floor stays at 22.15.

Nothing changes in `dependencies`, `optionalDependencies`, `peerDependencies` or `engines`. With permissions on, some calls that used to be allowed because supplied code ran as the leaf are now refused; see Behavior changes and Upgrade notes.

## ✨ Features

### Code a module made runs as that module, whoever runs it ([#597](https://github.com/CLDMV/slothlet/issues/597), [#624](https://github.com/CLDMV/slothlet/pull/624))

- **Code a caller hands to a leaf runs as the caller.** A leaf that converts, reads or calls a value it was handed runs code the value carries: `String(v)` runs a `toString`, `v.x` runs a getter or a Proxy `get` trap, `fn()` runs a callback. That code is the supplier's, so it runs as the supplier, with the leaf it runs inside as its ceiling: both have to be allowed. The leaf keeps its own rights for its own code, and `metadata.caller()` / `metadata.self()` report the supplier inside supplied code.
- **Code a module hands out runs as that module.** Closures, factories, classes and their instances, iterators, Proxies and accessors a module returns or stores keep running as the module that made them, with no ceiling from whoever calls them later.
- **`permissions.ceiling`** (`"leaf"` by default). With `"chain"`, the ceiling keeps every leaf the code was handed through on the way, not only the one it is running inside, and all of them are enforced.
- **`permissions.provenance`** (`true` by default). A module's own function that reaches another module's call by a route slothlet does not see (a shared object, a global, a built-in it replaced) still runs as that module, with the call it runs inside as its ceiling. `false` turns this off.
- **Frames are held to their script.** Slothlet records the SHA-256 of the source each instance module was loaded from (`CallSite#getScriptHash()`), so code compiled with `vm` or `Module#_compile` under a module's file name is not treated as that module's code.
- **Getters and setters on api objects** run as their module and are checked as calls of their node.
- **Module-initiated `api.add` and `reload`** build the added module as no module's code, while the host's own calls in the meantime stay the host's.
- **Values no module made** (a package's exports, a `node:` built-in's, slothlet's runtime) are handed out as they are, and everything callable they reach is made by no module too. Package files record their exports as they finish loading, through Node's module load hook.
- **Works with 3.23.0's ownership rules.** Every ceiling is held to the same ownership and rule checks as the caller, a kept `lockCaller.caller` run from handed-out code pins its module, and a node removed from the tree leaves what it made without standing.

See [docs/PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#code-a-caller-hands-to-a-leaf-runs-as-the-caller) for the placement rules and their limits.

## ⚠️ Behavior changes

These only apply while the permission system is on.

- **Supplied code needs both the supplier and the leaf to be allowed** ([#597](https://github.com/CLDMV/slothlet/issues/597)). A callback, getter or conversion a module hands to a leaf used to run with the leaf's rights. It now runs as the module that supplied it, under the leaf as a ceiling, so a `self.*` call from inside it is refused unless both may make it. Asking a permitted module to do something on its own account still works.
- **Handing over a leaf's own function is checked as calling it** ([#597](https://github.com/CLDMV/slothlet/issues/597)). Passing another module a function slothlet wraps, alone or inside plain data, gates the receiving call as though the caller had called that leaf through `self`.
- **Accessors on api objects are checked as calls** ([#597](https://github.com/CLDMV/slothlet/issues/597)). Reading or writing a getter or setter a module exports needs permission to call the api object that holds it.
- **A callback kept and run later from another flow is no longer tied to its supplier.** Pin it with `self.slothlet.lockCaller.caller(fn)` where it is registered, or have the supplier pin it with `self.slothlet.lockCaller(fn)` before handing it over.

## 🐛 Bug Fixes

### `new` on a lazy folder that has not loaded yet ([#685](https://github.com/CLDMV/slothlet/issues/685), [#686](https://github.com/CLDMV/slothlet/pull/686))

`new` on the stand-in a lazy folder hands out before it loads ran the engine's default construction on the stand-in: the constructor never ran, and every member of the object it returned was another stand-in. The stand-in now loads the chain and constructs its end, under the caller identity captured at `new`, and resolves to the instance. A stand-in held across `restart()` now resolves to the live end of its chain instead of building an object without the class's prototype.

A subclass's `super()` through a node that has not loaded, or is still loading, has to finish synchronously, which it cannot. It now throws `LAZY_SUBCLASS_BEFORE_LOAD` instead of handing back a broken instance; await the node first, or use eager mode.

### Cyclic members read through `self` close again ([#688](https://github.com/CLDMV/slothlet/issues/688), [#694](https://github.com/CLDMV/slothlet/pull/694))

Since 3.23.0, a plain object reached through `self` inside a module is a per-reader view held to the api path it was reached at. Views were cached per path, so following a cycle like `conn.self = conn` gave a longer path and a new view on every lap: `c.self.self !== c.self`, and deep equality (`isDeepStrictEqual`, `toEqual`) never found the cycle and ran until the stack ran out. A member read that walks back into a value already on its walk now gets that value's earlier view, so the cycle closes. A write round the cycle is held to that earlier, shorter path. Host reads are unchanged.

## 🔧 CI & tooling

- **Development needs Node 22.22; using slothlet still needs 22.15** ([#689](https://github.com/CLDMV/slothlet/pull/689)). The dev toolchain (chokidar 6) needs Node 22.22, which now sits in `devEngines` and is CI's minimum Node version. `engines.node` stays `>=22.15.0`, the floor slothlet's own code needs (`module.registerHooks()` and `CallSite#getScriptHash()`).
- **CI test workers sized to the runner** ([#696](https://github.com/CLDMV/slothlet/pull/696)). On CI the test runner now runs one worker per 3 GB of memory and per core (4 on GitHub's hosted runner) instead of a fixed 8, which had been starving the runner until GitHub dropped it mid-run. Local runs are unchanged.
- **devcheck removed from the repository** ([#684](https://github.com/CLDMV/slothlet/pull/684)). The `slothlet-dev` export condition already picks `src/` or `dist/` in a checkout. Nothing changes for installed packages; devcheck has not been published since 3.22.1.

## Upgrade notes

- Without a `permissions` config, nothing changes.
- With permissions on, code a module hands to another module's leaf is now checked as its own module under that leaf. If a supplied callback stops being allowed, grant the supplier the call it makes, or keep that work inside the leaf's own code.
- A callback a leaf stores and runs later (a timer, an event, a queue) needs `lockCaller` to keep its supplier's identity.
- To check every leaf supplied code passed through, set `permissions: { ceiling: "chain" }`.
- Subclassing a lazy node before it has loaded throws `LAZY_SUBCLASS_BEFORE_LOAD`: `await api.path` first and extend what it resolves to.
- Contributors need Node 22.22 or later to install and run the tooling; consumers still need 22.15 or later.
