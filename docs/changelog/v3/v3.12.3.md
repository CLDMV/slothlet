# Slothlet v3.12.3 Changelog

**Release Date**: August 2026
**Release Type**: Patch
**Branch**: `release/3.12.3`

---

## Overview

Version 3.12.3 is a **security patch** centered on caller attribution — making sure every read and call the permission system judges is attributed to the module actually responsible for it. The prior enforcement work assumed the caller identity it was handed was right; #245 closes six ways it could be wrong, each of which read as "no caller" or "someone else's caller" and therefore inherited authority it should not have had: identity was dropped at a module's first `await` in the live runtime, overwritten by concurrent calls, granted to non-module code through `self`, absent from deferred work (timers, microtasks, event listeners), absent from captured api references invoked later, and never consulted at all for enumeration/serialization reads (`Object.keys`, `JSON.stringify`).

The release also fixes `apiPath` derivation so a wrapper's identity matches the surface position it is actually reachable at (#243, #246) — nested namespaces no longer collapse onto one another for permissions, hooks, ownership, and versioning — plus a shutdown crash from deferred callbacks outliving their instance (#246), two EventEmitter-boundary fixes found in release review (cross-instance emitter cleanup, and a patched `removeAllListeners()` that silently removed nothing), and stricter validation for the `permissions.references` block. Test coverage is restored to 100% after the attribution work (#254). No breaking changes; every behavior change corrects enforcement that previously failed open, and the one compatibility escape (`permissions.references.capture: false`) is documented below.

## 🔒 Security & Permission Hardening (#245)

### Caller identity survives `await` in the live runtime

The live-bindings context manager tracked the executing module in a single slot and cleared it in a synchronous `finally` — which runs when an async module function reaches its first `await`, not when it finishes. Enforcement treats a read or call with no resolvable caller as host-initiated and exempt, so this failed open: with `defaultPolicy: "deny"` and no rules at all, `await null;` followed by `self.db.write.insert(...)` succeeded. Awaiting is mandatory for lazy access, which made this the ordinary shape of module code rather than a corner case. Identity is now held until the call settles.

### Concurrent calls cannot inherit each other's rights

Holding identity until a call settles fixed the sequential case but left the concurrent one: two calls with overlapping lifetimes cannot both be named by one mutable field, and a call resuming from its `await` read whichever module entered last — inheriting its rights. Identity now resolves per flow: while at most one call is suspended the field is necessarily that call's; beyond that, the caller is matched from the call stack against the suspended calls only. A stack frame that names several suspended calls at once is reported unresolved rather than guessed, so enforcement fails closed instead of falling through to the host exemption.

### `self` requires an executing module

`self` is the in-module view of the api, and what makes it safe is that every access through it is attributed to the module making it. The live runtime kept its store populated for the instance's whole lifetime, so any script able to import the runtime could read `self` and be resolved as the host — which is exempt from the rules, up to and including `slothlet.permissions.control.disable()`. Resolving `self` now requires an executing module (or a host-opened `run()`/`scope()` context); outside one it throws `RUNTIME_NO_ACTIVE_CONTEXT_SELF`.

### Deferred work is attributed to the module that scheduled it

A callback handed to a scheduling boundary runs after the call that registered it has returned, and under the live runtime it executed with no caller at all — which enforcement reads as host-initiated and exempt. A leaf's deferred work therefore ran with more authority than the leaf itself. Identity is now captured at registration — the only moment it exists — for timers, microtasks, `EventEmitter` listeners, and `EventTarget` listeners. The wrappers are otherwise transparent: return values pass straight back so `clearTimeout` keeps working, trailing arguments are forwarded, and promisify support is preserved.

### A captured api reference stays bound to the module that read it

A module could read an api function into a variable and invoke it later from a boundary carrying no caller — nothing reads `self` at that point, so the call arrived unattributed and was treated as host-initiated. A reference now carries the identity of whoever read it, recorded at the read. That identity is a **floor, not a substitute** for the live caller: both are checked, so handing a reference to a module with fewer rights lends it nothing, and a module cannot have denied work carried out for it by a permitted one. The floor travels down the whole path — capturing `self.db` and walking to a leaf later is refused for the same reason capturing the leaf directly is — and it holds even when the **host** does the reading through a module-lent reference. Compatibility escape for code that deliberately relied on the old behavior: `permissions.references.capture: false`.

### Read-gating covers enumeration and serialization

Read gating was enforced only on the `get` chokepoint. `Object.keys()` reaches keys through the `ownKeys` / `getOwnPropertyDescriptor` traps and `JSON.stringify()` reaches values through `toJSON`, none of which perform a `[[Get]]` — so a caller denied a terminal data value could still read it, and serializing a whole namespace returned every denied leaf beneath it in one call. Denied leaves are now **redacted** from those paths rather than disclosed (a partially-permitted namespace stays enumerable, and `getOwnPropertyDescriptor` agrees with `ownKeys` so a leaf cannot be withheld from listing yet still described). Each redaction still routes through `enforceAccess`, so it emits `permission:denied` and is never silent to an operator watching the audit stream. Direct reads still throw.

### `permissions.references` rejects arrays (release review)

`typeof [] === "object"`, so an array slipped past the block's validation and every option inside it read as unset — the author believes `capture` is off while the secure default is silently in effect. Arrays are now rejected with `INVALID_CONFIG`, the same way the `manifest` and `lifecycle` blocks already reject them.

## 🐛 Bug Fixes

### `apiPath` derives from the surface position a wrapper is reachable at (#243, #246)

A wrapper's `apiPath` is its identity — permissions, hooks, ownership, path metadata, and versioning all key off it — but it was derived independently of the composed surface and drifted from it in both directions. Anything below depth 1 was pathed from its own name alone (`deep.folder.config.get` was built as `folder.config.get`, and `deep.folder` / `deep2.folder` both collapsed onto `folder` — two distinct namespaces those subsystems could not tell apart). In the other direction, a level smart-flattening removed from the surface still contributed its segment, so a subtree mounted via `api.add()` gated on a path that does not exist on the api — the only rule form that worked named `exts.alpha.alpha.op` while the sole callable path was `exts.alpha.op`, which under `defaultPolicy: "deny"` read as "permissions deny everything at random". The rule is now uniform: a directory contributes a path segment exactly when it creates an api level. If you had written permission or hook rules against the old, wrong paths, see Upgrade notes.

### A pinned callback can outlive the instance that registered it (#246)

Pinning captures the instance so a deferred callback can re-enter its context when it runs — but that instance can be gone by then (a listener registered before shutdown, a timer already scheduled). Re-entering the missing context threw `CONTEXT_NOT_FOUND` with nobody to catch it, and slothlet's own uncaught handler then called `process.exit(1)` — so a host shutting one instance down while another was starting could be taken down by a stray callback from the first. The callback now runs **unpinned** when its instance is gone: with no context its `self` refuses, the same fail-closed answer every other unattributed deferred callback gets — losing access rather than gaining any.

### Emitter cleanup is scoped to the last shutdown (release review)

`cleanupEventEmitterResources()` ran on every instance's shutdown while its tracking structures span every instance in the process — so a sibling's shutdown cleared the original→wrapped listener mapping out from under a still-live instance (making its previously registered listeners irremovable through `removeListener`/`off`) and emptied the tracked-emitter set so the final shutdown had nothing left to release. The cleanup now sits under the same refcount gate as the prototype unpatching: the last instance out releases everything tracked.

### `removeAllListeners()` with no arguments actually removes (release review)

Node's `removeAllListeners` discriminates its remove-everything path by `arguments.length === 0`. The patched method forwarded an explicit `undefined`, which the original reads as "remove listeners for the event named `undefined`" — nothing — so while patching was active, the no-argument form silently removed no listeners for **every** caller in the process, while the tracking maps reported everything gone. The patched method now keys both its tracking cleanup and the forwarded call on the same `arguments.length` test.

### `rootUnwrap` declared in generated types (#246)

`rootUnwrap` was threaded through the builder and both mode entry points but never declared in their JSDoc, and `types/` is generated from JSDoc — so `tsc` failed the types build with `TS2339: Property 'rootUnwrap' does not exist`. Documented on `builder.buildAPI` and both `buildAPI` entry points; the regenerated declarations carry that addition and nothing else (#249).

## 🧪 Tests

### Coverage restored to 100% after the attribution work (#254)

The caller-attribution merge landed at 99.7%. Back to 100% with ~130 new test cases across three new suites and additions to two existing ones — including behavioral pins for the new enforcement surfaces: a lend-to-host test proving a captured namespace keeps the lender's permission floor even when the host does the reading, a construct-through-a-captured-view test for `Reflect.construct` with an explicit `newTarget`, and a third-module attribution test for the live resolver's fresh-field arm (whose previous coverage ignore wrongly claimed the arm undrivable — the ignore was removed). The remaining genuinely-undrivable arms carry documented `v8 ignore` markers stating whether each is unreachable or merely not reproducible in the suite.

### Multi-instance EventEmitter shutdown suite (release review)

New two-instance tests pin the emitter-cleanup fixes: a sibling's shutdown leaves a live instance's emitters, listeners, and `removeListener` mapping intact, and the last shutdown still releases everything tracked. The lifecycle suite additionally pins that no-argument `removeAllListeners()` genuinely detaches listeners while patching is active.

## Upgrade notes

- **No breaking changes** — but this release makes enforcement apply where it previously failed open, so code that (knowingly or not) relied on an attribution gap will now be refused. In each case the refusal is the rule you already wrote, applied to the module actually responsible.
- **`self` outside a module now throws.** Non-module code importing the runtime and reading `self` used to resolve with host authority in the live runtime; it now throws `RUNTIME_NO_ACTIVE_CONTEXT_SELF`. Host code should use the `api` object returned by `slothlet()` (or an explicit `api.slothlet.run()` / `.scope()` context), which carries the host's standing legitimately.
- **Captured references now enforce the reader's floor.** Stashing an api function or namespace in a variable and invoking it later — from host context, a timer, another module — is now checked against the module that captured it in addition to the live caller. If you depended on the old host-standing behavior, `permissions.references.capture: false` restores it; prefer restructuring so the host reads through its own `api` object.
- **Deferred work inherits its scheduler's rules.** Rules denying a leaf now also apply to the timers, microtasks, and event listeners that leaf schedules.
- **Enumeration and serialization are redacted.** `Object.keys()`, `getOwnPropertyDescriptor()`, and `JSON.stringify()` over partially-permitted namespaces now omit denied leaves instead of disclosing them. Code that inventoried a namespace it could not read will see the permitted subset.
- **`apiPath` corrections can affect rules keyed on the old paths.** If a permission or hook rule was written against a path the old derivation produced for a deeply nested namespace (e.g. `folder.config.get` for what is actually `deep.folder.config.get`), update the rule to the surface path — the old collapsed form no longer matches.
- **`removeAllListeners()` (no arguments) now works under patching.** It previously removed nothing while reporting success; code calling it now actually sheds its listeners.
- **Multi-instance emitter cleanup timing.** In processes running several slothlet instances, tracked-emitter cleanup now happens when the last instance shuts down instead of on every shutdown. Single-instance hosts see no difference.
