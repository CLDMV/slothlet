# Slothlet v4.0.0 Changelog

**Release Date**: November 2026
**Release Type**: Major
**Branch**: `next` → `master`

---

## Overview

Version 4.0.0 renames most of slothlet's public surface so that every name says one thing and every group of options reads the same way: config keys, method options, `api.slothlet` methods, error codes and their details, event, hook and diagnostics payloads, manifest fields and package entry points. Unknown config keys and method options are now errors, so a config that boots on v4 is a v4 config. A handful of defaults change too: routines run and stack by default, `_` and `__` privacy follows the owning module, and the init context is copied.

> [!IMPORTANT]
> **Upgrading from 3.x? Start with the [v3 → v4 migration guide](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md).** It covers every change you have to understand yourself and carries the full rename tables. Most of the move is mechanical: `npx @cldmv/slothlet-migrate --write` rewrites what it can prove, and `npx @cldmv/slothlet-migrate audit .` lists every v3 name still in use. This changelog summarises; the guide has the detail.

v4.0.0 also ships everything queued for 3.25.0, which was never released: an instance clock, a `helpers` option, the definer-and-caller rule for `self` calls with `permissions.caller.attribution`, api nodes that behave like the module's own objects, built-in capabilities and permissions mode `"strict"`, and a long list of permission, composition, ownership and lazy-mode fixes found in the release review.

`run()` and `scope()` are now isolated in every permission mode on both runtimes, and each one runs on a snapshot of the instance as of its start: later changes to the instance don't reach an open run, and what a run changes stays in it (see [Runs read a snapshot of the instance](#runs-read-a-snapshot-of-the-instance)). To keep flows apart, the async runtime installs an `async_hooks` hook for every instance and the live runtime V8's promise hooks, which cost a little on every promise step in the process (see [Run isolation and process-wide hooks](#run-isolation-and-process-wide-hooks)). With permissions on, rule targets name an access level (`:call`, `:read`, `:access`, `:write`, `:full`), there is no write without the read, and code the replaced modules handed out before a `restart()` is refused after it.

Module code may no longer import a file that is an api leaf, in any permission mode: one leaf reaches another through `self`, and code two leaves share lives in lib files beside the api folder (see [Module code cannot import leaf files](#module-code-cannot-import-leaf-files-947)). The host's own imports are unchanged.

`engines.node` stays `>=22.15.0` and `devEngines` stays `>=22.22.0`. With permissions on, an async-runtime instance on Node 22 now needs `--experimental-async-context-frame` for `"strict"`, and `"on"` warns without it (see [Permissions baseline](#permissions-baseline-and-strict-mode)).

## 💥 Breaking Changes

Every item below has a section or table row in [docs/MIGRATION.md](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md).

### Renames

- **Config keys move to their v4 names and groups** ([#847](https://github.com/CLDMV/slothlet/pull/847)). New groups `loader`, `permissions.caller`, `permissions.gating`, `routines` and `versioning`; for example `dir` → `base`, `apiDepth` → `depth`, `backgroundMaterialize` → `loader.materialize`, `resolveModuleSpecifier` → `loader.resolve`, `permissions.readGating` → `permissions.gating.read`, `permissions.defaultPolicy` → `permissions.policy`, `hook.suppressErrors: true` → `hook.errors: "suppress"`, `versionDispatcher` → `versioning.dispatcher`. Deprecated v3 aliases (`dir`, root `collision`, `allowMutation`, `collectLifecycleHooks`, `permissions.enabled`, `suppressFixes`) are removed. See the [config table](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#reference-tables).
- **Method options move to their v4 names** ([#867](https://github.com/CLDMV/slothlet/pull/867)), and unknown option keys are refused instead of ignored.
- **`api.slothlet` methods are renamed, moved and folded** ([#850](https://github.com/CLDMV/slothlet/pull/850)), for example `permissions.addRule()` → `permissions.rules.add()`. `materialize.materialized` is `materialize.complete`, and the `api.slothlet.run` and `api.slothlet.scope` aliases are gone; use `context.run` and `context.scope`. A module's manifest rules are now validated before it mounts.
- **Error and warning shape** ([#849](https://github.com/CLDMV/slothlet/pull/849)). `SlothletError` and `SlothletWarning` take `(code, details, { cause })`. `.context` is `.details`, `originalError` is the standard `cause`, and the `validationError` and `stub` flags are gone. Codes are renamed into families (`WARNING_*`, `PERMISSION_*`, `TYPESCRIPT_*`, `CONTEXT_*`) and detail keys use the v4 data words. See [Error and warning details](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#error-and-warning-details).
- **Payloads and reported paths** ([#859](https://github.com/CLDMV/slothlet/pull/859), [#861](https://github.com/CLDMV/slothlet/pull/861)). Every api path slothlet reports is a segments array: `leaves()`, event, lifecycle and audit payloads, error details, `node().path`. Lifecycle, event, audit and hook payloads use the v4 data words (`hasError` → `errors.length > 0` in always hooks, the error hook's `source` → `origin`, `timestamp` → `at` as a `clock.now()` number). `diag.inspect()`, `context.diagnostics()` and `diag.caches.get()` have new shapes. See [Paths, kinds and caller objects in data](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#paths-kinds-and-caller-objects-in-data).
- **`slothlet.caller()` returns the caller object** `{ path, module, metadata, version }` ([#846](https://github.com/CLDMV/slothlet/pull/846)), the same shape permission entries, around hooks and the version dispatcher use.
- **`instance.id` replaces `instanceID`** ([#854](https://github.com/CLDMV/slothlet/pull/854)). The runtime entries export a frozen `instance` whose `id` is the running instance's id; `api.slothlet.instance.id` reads it from the host. The `reload` option `keepInstanceID` is `instance: "keep" | "new"`.
- **Framework-private names move to `____` and `___`** ([#863](https://github.com/CLDMV/slothlet/pull/863)). A module may now export `_impl`, `_materialize` and the like freely; code that read slothlet's own `_impl`, `__state` or `_materialize` loses them.
- **i18n `language.set`** ([#853](https://github.com/CLDMV/slothlet/pull/853)). `setLanguage`, `setLanguageAsync`, `getLanguage` and `initI18n` fold into `language.{get,set}` on `@cldmv/slothlet/i18n` and `api.slothlet.i18n`. `language.set` is synchronous in Node and returns a promise only where the load is asynchronous (the browser).

### Module code cannot import leaf files ([#947](https://github.com/CLDMV/slothlet/pull/947))

- **An import of a leaf file made by module code is refused with `MODULE_LEAF_IMPORT_REFUSED`**, with permissions on, off or `"disabled"`, whatever the rules say. Module code is every file slothlet loads for an instance: its api files and the lib files they load. A leaf file is any file slothlet composes into an api tree, under the base folder or an `api.add()` mount. The refusal covers a sibling, a file in another folder of the tree and a file of another mount, by static `import`, `export … from`, `import()`, `import.meta.resolve()`, `require()` and `require.resolve()`. In v3 such an import loaded a second copy of the file with its own module state.
- **Reach other leaves through `self`, and keep shared code in lib files** in a folder beside the api folder, outside the tree. A lib file a leaf loads is held to the same rule, so it cannot pass a leaf file on.
- **Host code is exempt.** The host and its tests import leaf files as before, and a file no live instance composes is a lib file.
- **An api shipped as an npm package is held to the same rule.** Its leaf and lib files are refused a leaf file whether they name it by a relative path, the package's own name, an `#imports` entry or another package's bare specifier.
- **In the browser the import is not refused.** No import is seen there, so a module that imports a leaf file gets its own copy of the file, which is never the leaf and does not share its module state. The same code is refused under Node and under vite or vitest, so move it to `self` or a lib file even when the browser build works.

An eager build of a tree whose file imports a leaf file fails with that file's `MODULE_IMPORT_FAILED`, the refusal as its cause; in lazy mode the folder holding the file fails as it loads. See [Module code cannot import leaf files](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#module-code-cannot-import-leaf-files) in the migration guide and [MODULE-STRUCTURE.md](https://github.com/CLDMV/slothlet/blob/master/docs/MODULE-STRUCTURE.md#leaf-files-are-not-imported).

### Package entry points ([#839](https://github.com/CLDMV/slothlet/pull/839))

Internals moved to package `#` imports. The `./slothlet`, `./helpers/*`, `./modes/*`, `./builders/*` and `./processors/*` subpaths are no longer exported. New entry points: `@cldmv/slothlet/vite` (the vitest plugin), `@cldmv/slothlet/files` (the browser file list: `files.generate`, `importmap`, `assets`, `resolver`, `specifiers`) and `@cldmv/slothlet/sanitize`. `@cldmv/slothlet/i18n` has its own entry file, and `generateTypes` from `@cldmv/slothlet/typegen` is `generate`. The optional `@cldmv/slothlet-i18n` and `@cldmv/slothlet-types` peers move to `^4.0.0`. See [Package entry points](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#package-entry-points).

### Strictness ([#856](https://github.com/CLDMV/slothlet/pull/856), [#842](https://github.com/CLDMV/slothlet/pull/842))

- `slothlet()` checks its config against one schema. A key it does not list, at any depth, throws `INVALID_CONFIG_UNKNOWN_KEY` with `{ where, key, path }`. v3 names are not kept as aliases.
- `api.slothlet.api.modules.add` only accepts discover results this instance produced; any other object is read as options and fails validation.

### Behaviour and defaults

- **The init context is copied, and `context.set` exists** ([#843](https://github.com/CLDMV/slothlet/pull/843)). Changing the object passed as `context` no longer changes the live context. `api.slothlet.context.set(key, value)` or `context.set({ … })` changes it at runtime; it is host only unless a rule allows `slothlet.context.set`.
- **Warnings are recorded per instance** ([#848](https://github.com/CLDMV/slothlet/pull/848)) on `api.slothlet.warnings.get()` / `.clear()`, printed or not. `silent: true` only decides whether they reach the console. `SlothletWarning.captured`, `clearCaptured()`, `suppressConsole` and `api.slothlet.diag.SlothletWarning` are gone.
- **Permission control folds into `control.mode()` and `control.gating.read()`** ([#851](https://github.com/CLDMV/slothlet/pull/851)). `control.enable()`, `disable()`, `readGating()` and the `enabled` / `readGatingEnabled` accessors are gone. `permissions.mode` accepts `true` / `false` as aliases of `"on"` / `"off"`.
- **`api.remove` takes the path first** ([#852](https://github.com/CLDMV/slothlet/pull/852)): the scoped form is `remove(apiPath, id)`. There is no runtime check for the v3 order, so search for scoped `remove` calls or let `slothlet-migrate audit` flag them.
- **`hidden` globs can re-include with `!`** ([#855](https://github.com/CLDMV/slothlet/pull/855)). The built-in rule that hides `.` and `__` entries is the bottom layer of `hidden`, and the last matching glob decides. `scanHiddenFolders` is removed; `hidden: ["!**/.*/", "!**/__*/"]` does what it did.
- **`slothlet.module.json` format 2** ([#845](https://github.com/CLDMV/slothlet/pull/845)). `schema: 2`, `mount` and `base` replace `schemaVersion`, `mountPath` and `apiDir`. Format 1 files are still read, with a deprecation warning per field. Discover and mount results report segments arrays and `version: { default, tag }`.
- **Routines run and stack by default** ([#869](https://github.com/CLDMV/slothlet/pull/869)). `routines` is a group: `routines.entries` holds the array (the bare-array form is refused), `routines.auto` defaults to `true` and `routines.stack` defaults to `true`. Set either to `false` to keep the v3 behaviour.
- **`loader.materialize` takes a function** ([#868](https://github.com/CLDMV/slothlet/pull/868)), called once per instance on `materialized:complete` (at once if it has already completed). Any other non-boolean value now throws `INVALID_CONFIG`.
- **`tracking` is removed; `loader.materialize` is the only switch** ([#876](https://github.com/CLDMV/slothlet/pull/876)). v3's `tracking: true` and `tracking: { materialization: true }` did what `loader.materialize: true` does; passing `tracking` now throws `INVALID_CONFIG_UNKNOWN_KEY`, and `materialized:complete` fires only with `loader.materialize` on. `npx @cldmv/slothlet-migrate` folds it into `loader.materialize`.
- **Private members are decided by module** ([#862](https://github.com/CLDMV/slothlet/pull/862)). An `_` or `__` export is private to the module that owns it, not to its folder. `permissions.private.scope: "folder"` keeps the 3.x rule.
- **`node()` replaces the `__` fields on nodes** ([#846](https://github.com/CLDMV/slothlet/pull/846)). `api.slothlet.node(target)` returns one frozen report (`path`, `file`, `folder`, `module`, `mode`, load state, `callable`, `type`, and more). `metadata.get` is synchronous and returns user metadata only; `getFor`, `getForVersion`, `setFor`, `setForVersion` and `removeFor` fold into `get`, `set` and `remove`.
- **Built-in capabilities are refused to module code until a rule opens them** ([#829](https://github.com/CLDMV/slothlet/pull/829)). While permissions are on, making code from strings (`capability:code`), importing `data:` and `blob:` URLs (`capability:imports`) and registering module hooks (`capability:loader`) need a rule naming the capability for that leaf. A rule that allows `**` opens none. If a module builds functions from strings, add a `capability:code` rule for its leaf.
- **Lazy mode under vitest needs the plugin** from `@cldmv/slothlet/vite` ([#829](https://github.com/CLDMV/slothlet/pull/829), [#860](https://github.com/CLDMV/slothlet/pull/860)), with the forks pool; the threads pool is refused. See [TESTING.md](https://github.com/CLDMV/slothlet/blob/master/docs/TESTING.md#per-instance-helpers-under-vitest-the-cldmvslothletvite-plugin).
- **`FOLDER_INVALID` has new text, and the uncaught-error output prints `cause` and `details`** ([#915](https://github.com/CLDMV/slothlet/pull/915)). The message no longer names v3's `dir`: it reads "the path must be a non-empty string that points to an existing folder", in every language. The handler the package entry installs for an uncaught slothlet error prints the error's `cause` and `details` (v4's shape) instead of v3's `originalError` and `context`. Code that matches the message text, or parses that output, needs updating; match `err.code` instead.
- **The package entry no longer takes over uncaught exceptions** ([#937](https://github.com/CLDMV/slothlet/pull/937), [#932](https://github.com/CLDMV/slothlet/issues/932)). v3 registered an `uncaughtException` listener that rethrew every other error, so Node exited with code 7 even when the host had a handler of its own. The printer is now an `uncaughtExceptionMonitor`: a host with its own `uncaughtException` handler gets every error, a `SlothletError` included, and the readable `SlothletError` output (and exit code 1) appears only when nothing else handles it. Any other unhandled error ends the process as it would without slothlet.

### Runs read a snapshot of the instance

- **`run()` and `scope()` run on a snapshot of the instance as of their start** ([#915](https://github.com/CLDMV/slothlet/pull/915)). A run reads the api tree, every value reachable through it, the permission rules, hooks, metadata, versioning and the context as they were when it started. Nothing is copied when a run opens: the instance saves an object just before it first changes it while a run is open, and each run reads the version for its start.
  - Changes the instance makes after a run started don't reach that run: a later `api.x = …`, a `context.set()`, a change to a `Map`, `Set` or `Date`, or a module's change through `self`. A run opened afterwards reads the new value.
  - What a run writes doesn't reach the instance.
  - An `EventEmitter` or `EventTarget` is a shared live object: listeners a run adds, events either side emits and a plain property a run sets on it reach the instance.
  - A `Map`, `Set`, `Date`, typed array and the like read in a run is the run's own copy, so comparing it with `===` to the instance's object is `false`. `structuredClone`, `instanceof` and the built-in methods work on it as usual.
  - A run that lasts, such as a server's `listen()` called inside `run()`, keeps reading the instance as it was when the run opened, so it doesn't see later config. Open such a server outside the run, or read changing values through something the snapshot doesn't cover.
  - While a run of the instance is open, a promise a call returns is a new promise object, not the one the module returned, and it settles one microtask later with the same value.
  - A module's own variables, `#private` methods, live resources (sockets, streams, timers, promises, weak collections) and references kept from before the run are outside the snapshot. The full list is in [CONTEXT-PROPAGATION.md](https://github.com/CLDMV/slothlet/blob/master/docs/CONTEXT-PROPAGATION.md#what-a-runs-snapshot-covers-and-what-it-doesnt).
- **`self` in a run is the run's own by default** ([#876](https://github.com/CLDMV/slothlet/pull/876)). `scope.isolation` defaults to `"full"`: a `self` write made in a run stays in the run and is dropped when it ends. `scope: { isolation: "partial" }`, or `isolation: "partial"` per call, shares the instance's `self` as v3 did.
- **Inside a run, the host's `api` is the instance** ([#915](https://github.com/CLDMV/slothlet/pull/915)). A change the host makes through `api` in a run reaches the instance. To keep host changes in the run, use the run's own view, which `api.slothlet.context.run.self()` and `scope({ self: true })` hand to the callback (see Features below).

### Restart and permissions

- **Code the replaced modules handed out before `restart()` is refused after it** while the permission system is on ([#915](https://github.com/CLDMV/slothlet/pull/915)): a function, bound function, closure or method a module returned, and a snapshot its call took, whether the host runs it outside any call or inside a `run()` / `scope()`. A `restart()` inside a run does the same for that run's copy. Read the member from `api` again to reach the new instance's code. `reload()` keeps such code working, and with the permission system off it keeps working after a restart too. See [RELOAD.md](https://github.com/CLDMV/slothlet/blob/master/docs/RELOAD.md).
- **A run open across a failed `restart()` is refused as after `shutdown()`** ([#915](https://github.com/CLDMV/slothlet/pull/915)): the copy it kept belongs to the instance that ended, so its modules' calls through `self` throw `CONTEXT_NOT_ACTIVE_SELF`.
- **`permissions.caller.capture: false` restores host standing only where no module code runs** ([#915](https://github.com/CLDMV/slothlet/pull/915)). The opt-out covers the host calling a reference a module handed it. A reference a module's own code invokes, a callback the module defined included, is still enforced as that module, and the async runtime now treats a host call outside every flow as the live runtime does.

### Rule access levels ([#876](https://github.com/CLDMV/slothlet/pull/876))

- **A rule target's suffix names the access level it governs**: `:call`, `:read`, `:access` (call and read), `:write` (read and write) or `:full` (call, read and write). A target with no suffix is `:access`, so existing call and read rules keep their meaning. `:full` counts as a write rule everywhere `:write` does. See [PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#access-levels).
- **A `:write` allow grants the read as well as the write**, so under `policy: "deny"` a `:write` grant alone lets its callers read and write those members. A `:write` deny refuses the write alone; a deny that takes the read away refuses the write too.
- **A write is held to the read rules, not the call rules**: a `:call` deny keeps a module from calling a function, no longer from replacing it where a write rule grants that. `self.access()` and `global.check.access()` answer whether both the call and the read are allowed.
- **A rule target with an unknown suffix is refused** with `PERMISSION_RULE_INVALID` wherever a rule comes in: the config's `permissions.rules`, `rules.add`, a manifest, the `permissions` option of `api.add`, and rules module code registers. In v3 a misspelt suffix (`secret.**:wirte`) was kept as a rule on the literal target and matched nothing. A `capability:` target takes no suffix check.
- **A rule target whose path holds a `:` of its own, or names no path before its suffix, is refused** with `PERMISSION_RULE_INVALID` in the same places ([#942](https://github.com/CLDMV/slothlet/pull/942), [#941](https://github.com/CLDMV/slothlet/issues/941)). `vault.secret:read:write` and `:write` were accepted and matched nothing, since an api path holds no `:`. An `api.add` `permissions` option given as an array or a string, or with an `allow` / `deny` that is not an array, was ignored and is now refused with `INVALID_ARGUMENT` before anything mounts.

### Run isolation and process-wide hooks

- **`run()` and `scope()` are isolated in every permission mode, on both runtimes** ([#876](https://github.com/CLDMV/slothlet/pull/876), [#887](https://github.com/CLDMV/slothlet/issues/887), [#889](https://github.com/CLDMV/slothlet/issues/889)). No code sees or takes another flow's context, and each flow's calls report their own caller, with no `permissions` config, `"off"`, `"disabled"`, `"on"` or `"strict"`. The permission mode decides only what code may do. On the live runtime, concurrent flows interleaving across `await`s, timers, immediates, `nextTick`, microtasks and listeners each keep their own context, and a `run()` opened beside a waiting one starts from the instance's own context. In a browser the code after a bare `await` is the one gap (no promise hooks); callbacks registered through the patched boundaries are carried.
- **The async runtime installs an `async_hooks` hook while any async-runtime instance exists**, in every permission mode, and removes it after the last one shuts down. Node runs it for every promise and callback in the process: on Node 26 about 0.9 µs per `await` of a `then()` outside every flow and about 1.3 µs inside a `run()` or a call, and about 0.9 µs / 3.2 µs per `setImmediate()` outside / inside.
- **The live runtime installs V8's promise hooks (`v8.promiseHooks`, not `async_hooks`) while any live instance exists in Node**, in every permission mode: about 0.15 µs per promise job in the process, and about 1 µs more per callback a flow registers through a patched boundary. A process with only live instances makes no `async_hooks` hook and no `AsyncLocalStorage`.
- **The live runtime carries the run into the callbacks of `fs`, `dns` and `crypto`** ([#892](https://github.com/CLDMV/slothlet/issues/892)). While a live instance exists, every callback form in `node:fs`, `node:dns` (module and `Resolver`) and `node:crypto` is replaced on the module object with a wrapper that runs the callback in the flow and as the caller that made the call (about 1 µs per call inside a run, 0.4 µs outside). A reference taken before the first live instance keeps Node's own function. On the async runtime, overlapping `crypto.randomInt(n, cb)` calls each keep their own flow too. The full list is in [CONTEXT-PROPAGATION.md](https://github.com/CLDMV/slothlet/blob/master/docs/CONTEXT-PROPAGATION.md#concurrent-run-and-scope-flows-in-the-live-runtime).
- **A function is the same value in every run.** A function read through the api compares `===` inside and outside a `run()` and in every run (under `"precise"`, it is its module's one stand-in), and a job a flow's own code hands Node (a promise reaction, timer, immediate, microtask or listener) runs in that flow.
- **A thenable a `run()` / `scope()` callback returns is settled inside the run** ([#890](https://github.com/CLDMV/slothlet/issues/890)). `run()` and `scope()` always return a promise.

### Writes and metadata

- **There is no write without the read** ([#876](https://github.com/CLDMV/slothlet/pull/876)). With permissions on, every module write that passes the ownership and write rules is also held to the read of the member it changes, as the read gate decides it (a `:write` or `:full` allow among the rules): assignment, `defineProperty`, `delete`, `Reflect.set`, writes through a held node or view, class prototype members, data objects, and `api.add` / `api.remove` from module code. Replacing a node is held to every member beneath it, a deny on an object member of a module's data covers writes beneath it, and giving a value a member it inherits or one the language reads by itself (`toJSON`, `toString`, `valueOf`) is held to the value's own path. A function member is held to the read too, so a `:call` deny alone doesn't stop a granted replacement (see [Rule access levels](#rule-access-levels-876)). Permissions off or disabled are unchanged.
- **A member a module creates at runtime is owned by that module** ([#888](https://github.com/CLDMV/slothlet/issues/888)), with what a created object holds. Removing the module removes it, a scoped removal removes just that member, and a full reload keeps neither.
- **Metadata with a cycle through an array is refused** with `INVALID_ARGUMENT`, like a cycle through plain objects, at every entry point ([#876](https://github.com/CLDMV/slothlet/pull/876)).
- **Reload instance IDs carry a random part**, `<id>_reload_<time>_<random>`, and are claimed before the old one is let go. A reload that cannot claim one fails with `INSTANCE_ID_IN_USE` and leaves the instance working on its current ID.

### Carried from the unreleased 3.25.0

These shipped on `next` for 3.25.0 and reach users for the first time in 4.0.0. The [migration guide](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#upgrade-notes-carried-from-325) has an example for each.

- A folder's only file with a default-export function is that function at the folder's path, whatever the file is called, and a folder whose only entry is a folder of the same name is one level again, as in 2.x ([#743](https://github.com/CLDMV/slothlet/issues/743), [#742](https://github.com/CLDMV/slothlet/pull/742)). A node's recorded path (used by rules, hooks and ownership) is now the path it is reached at.
- `**` matches zero or more segments wherever a pattern is compiled: permission rules, hooks, routine names and `hidden` globs ([#734](https://github.com/CLDMV/slothlet/pull/734), [#742](https://github.com/CLDMV/slothlet/pull/742)). Write `x.*.**` to skip `x` itself.
- Call, write and hook rules prefer the more specific pattern of the same kind, then the layer, then the order ([#742](https://github.com/CLDMV/slothlet/pull/742)).
- Event levels follow the permission mode: with permissions off or disabled, every `event.on()` subscription is delivered at `allow`, with its payload ([#742](https://github.com/CLDMV/slothlet/pull/742)).
- A `self` call is allowed only when the calling function's definer and its caller both are, and a call whose caller cannot be determined is refused in every mode ([#726](https://github.com/CLDMV/slothlet/issues/726), [#734](https://github.com/CLDMV/slothlet/pull/734)).
- Module code that comes to hold one of slothlet's internal exports is refused with `MODULE_INTERNAL_NOT_IMPORTABLE` ([#742](https://github.com/CLDMV/slothlet/pull/742)).

## ✨ Features

### `@cldmv/slothlet-migrate` ([#840](https://github.com/CLDMV/slothlet/pull/840), [#858](https://github.com/CLDMV/slothlet/pull/858), [#870](https://github.com/CLDMV/slothlet/pull/870))

A new package that moves code from v3 to v4. `npx @cldmv/slothlet-migrate` prints a dry-run diff; `--write` applies it, splicing only the changed spans so the rest of each file stays byte-identical. It rewrites `slothlet()` configs, method calls and their options, permission rule targets, imports, error code strings compared with `err.code`, `slothlet.module.json` files and the `slothlet typegen` settings in `package.json`, and reports everything it cannot prove with file, line and the v4 replacement. `slothlet-migrate audit <dir>` changes nothing and lists every v3 surface still in use, including data keys no rewrite can safely touch; it exits `1` on findings, `0` when clean and `2` on a usage or parse error, with `--json` for CI. The migration guide's tables are generated from the same data the tool reads. See the [tool's README](https://github.com/CLDMV/slothlet/blob/master/packaging/slothlet-migrate/README.md).

### Permissions mode `"strict"` and the baseline ([#829](https://github.com/CLDMV/slothlet/pull/829))

`permissions.mode: "strict"` is `"on"` plus a met baseline, fixed for the life of the instance (`PERMISSION_STRICT_FIXED` if code tries to switch it). The baseline is a set of facts about the host checked as an instance starts: in a browser, a page CSP that refuses code from strings and `blob:` / `data:` scripts; in Node, Node's `AsyncContextFrame`; under vitest, the `@cldmv/slothlet/vite` plugin. `api.slothlet.permissions.control.report()` shows the baseline, the capabilities and which callers rules open them to. See [PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#strict-mode-the-baseline-and-capabilities).

### Permissions baseline and strict mode

The baseline gains an `async-context-frame` check for async-runtime instances ([#876](https://github.com/CLDMV/slothlet/pull/876)). The live runtime keeps nothing in an `AsyncLocalStorage`, so a live instance reports no such check.

- **Node 22 needs `--experimental-async-context-frame` for `"strict"`.** Without it the check is not met and a strict async-runtime instance does not start (`PERMISSION_BASELINE_UNMET`).
- **Under `"on"`, it warns.** Each unmet check raises one `WARNING_PERMISSION_BASELINE_UNMET` naming it, and the instance starts.
- On Node 24 and later the frame is on unless Node runs with `--no-async-context-frame`, on the command line or in `NODE_OPTIONS`. The warning names the fix for the running Node.

### `permissions.search` ([#948](https://github.com/CLDMV/slothlet/pull/948))

`permissions.search: { depth, properties }` sets how far a value handed into a call, and data returned from one, is searched for code. The defaults are 4 levels and 512 properties for both directions; arguments used to stop at 256 properties. `depth` takes 1 to 64 and `properties` 1 to 65536, and anything else throws `INVALID_CONFIG`. Past the limit, returned data fails closed and comes back as a stand-in, while a leaf's function nested deeper in an argument is not found. Raising either value searches further at a cost on every call handed such a value. The setting is per instance and host only: an `api.add` `permissions` option that carries `search` is refused. See [How far values are searched](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#how-far-values-are-searched) and [CONFIGURATION.md](https://github.com/CLDMV/slothlet/blob/master/docs/CONFIGURATION.md#permissionssearch).

```javascript
const api = await slothlet({ base: "./api", permissions: { policy: "deny", search: { depth: 6, properties: 1024 }, rules } });
```

### `run.self()` and `scope({ self: true })`

`api.slothlet.context.run.self(contextData, fn, ...args)` and `scope({ …, self: true })` call `fn(view, ...args)` with the run's own view: exactly what module code's `self` resolves to in that run ([#915](https://github.com/CLDMV/slothlet/pull/915)). Under the default `"full"` isolation a change the host makes through `view` stays in the run, as a module's change through `self` does, while a change through `api` reaches the instance. Opened by module code, the view is the module's own `self`. `run.self` is checked under the rules of `slothlet.context.run`, and a rule on `slothlet.context.run.self` applies to it alone. It is typed on the composed api's `slothlet` namespace. See [CONTEXT-PROPAGATION.md](https://github.com/CLDMV/slothlet/blob/master/docs/CONTEXT-PROPAGATION.md#apislothletcontextrunselfcontextdata-callback-args).

### Other additions

- **`clock`** ([#742](https://github.com/CLDMV/slothlet/pull/742)): the functions an instance reads the time with and schedules its deferred work with (`now`, `set`, `clear`). Slothlet takes `Date.now` and the timers as it loads, so this is how a test with fake timers moves slothlet's own time.
- **`helpers: "instance" | "module"`** ([#742](https://github.com/CLDMV/slothlet/pull/742)). `"module"` loads each helper file once per importing api file, so helper state is no longer shared between api files. `"instance"` (the default) keeps one copy per instance.
- **`permissions.caller.attribution: "precise" | "fast"`** ([#734](https://github.com/CLDMV/slothlet/pull/734)) chooses how the definer of a function is found. `permissions.caller.ceiling` and `permissions.caller.provenance` (from 3.24.0) move into the same group.
- **`permissions.gating.buffers`** ([#742](https://github.com/CLDMV/slothlet/pull/742)): whether a typed array or `Buffer` one module hands another has its keys listed, so one carrying a member of its own is handed over as a view (`false`, `true`, or a size limit in kilobytes).
- **Api nodes behave like the module's own objects** ([#713](https://github.com/CLDMV/slothlet/pull/713), [#742](https://github.com/CLDMV/slothlet/pull/742)). A write through the api reaches the module's object; descriptors, prototypes, `isFrozen`, `JSON.stringify` key order, `Function.prototype.toString` and `structuredClone` answer as on the plain value; a module that may read but not write gets a checked view.
- **`api.slothlet.same(a, b)`** ([#876](https://github.com/CLDMV/slothlet/pull/876)) tells whether two values are the same object once slothlet's own layers (a node, a prototype's handle, a view, a stand-in) are taken off each, so a module handed a prototype's handle can tell it is the prototype it imported. It answers a boolean, runs none of the values' code, and every module may call it through `self.slothlet.same`. See [PERMISSIONS.md](https://github.com/CLDMV/slothlet/blob/master/docs/PERMISSIONS.md#telling-two-values-apart-slothletsame).
- **Rule access levels** ([#876](https://github.com/CLDMV/slothlet/pull/876)): `:call`, `:read`, `:access`, `:write` and `:full` say which of a call, a read and a write a rule decides (see [Rule access levels](#rule-access-levels-876)).
- **Paths in or out as segments.** Every path slothlet accepts takes a dotted string or an array, one element per segment, and messages join reported segments for display ([#845](https://github.com/CLDMV/slothlet/pull/845), [#859](https://github.com/CLDMV/slothlet/pull/859)).

### Runs, reload and restart

- Back-to-back runs that never yield a macrotask no longer pile up memory: finished run copies are released in batches on a microtask as well ([#909](https://github.com/CLDMV/slothlet/issues/909)).
- A run's code keeps working across a `reload()`: calls stay in the run while the instance moves to a new ID, code made in the run before the reload keeps its definer's standing when passed into another module's call ([#916](https://github.com/CLDMV/slothlet/issues/916)), and a run's first call to a lazy node it had not loaded yet is no longer refused ([#919](https://github.com/CLDMV/slothlet/issues/919)).
- Code a module made before a reload or restart acts on the rebuilt instance when called outside any run, instead of throwing `CONTEXT_NOT_ACTIVE_SELF` ([#912](https://github.com/CLDMV/slothlet/issues/912)).
- On the async runtime, code run through a snapshot or `AsyncResource` made in a run reaches the reloaded tree ([#911](https://github.com/CLDMV/slothlet/issues/911)); on the live runtime, an `AsyncResource` made in a run keeps the run's context across `restart()` ([#910](https://github.com/CLDMV/slothlet/issues/910)).
- On the live runtime, CommonJS code that awaits before reading `self` keeps its definer's standing when passed into another module's call ([#917](https://github.com/CLDMV/slothlet/issues/917)).
- On the live runtime, work a run schedules keeps the run's context after the run's callback returns ([#894](https://github.com/CLDMV/slothlet/issues/894)), including after a `reload()` on both runtimes ([#897](https://github.com/CLDMV/slothlet/issues/897)), and the `process.nextTick` patch survives vitest's write-back ([#895](https://github.com/CLDMV/slothlet/issues/895)).
- A failed reload leaves the instance as it was: calls keep answering from the copy it had instead of throwing `CONTEXT_NOT_FOUND` ([#899](https://github.com/CLDMV/slothlet/issues/899)), and it leaves no context stores behind ([#896](https://github.com/CLDMV/slothlet/issues/896)).
- The instance ID keeps the same length across reloads, so repeated reloads of a TypeScript instance no longer fail on a too-long cache folder name ([#893](https://github.com/CLDMV/slothlet/issues/893)).
- `restart()` called from a module rebuilds as the host instead of failing with `PERMISSION_DENIED` ([#903](https://github.com/CLDMV/slothlet/issues/903)), and runs open across a restart move to the instance's new ID when the rebuild fails ([#915](https://github.com/CLDMV/slothlet/pull/915)).
- `reload(path)` keeps which add won a merge collision ([#904](https://github.com/CLDMV/slothlet/issues/904)).
- Metadata written while a full reload builds lands in the new copy, and in lazy mode a node's metadata is one entry whether the node has loaded or not ([#918](https://github.com/CLDMV/slothlet/issues/918)).
- A run's version default and version metadata stay in the run, and `api.add()` / `remove()` that change the root object keep a run on the root as of its start ([#915](https://github.com/CLDMV/slothlet/pull/915)).
- On the live runtime, a timer set in a run and re-armed with `refresh()` from its callback holds the run again instead of firing after the run's copy is gone ([#933](https://github.com/CLDMV/slothlet/issues/933), [#937](https://github.com/CLDMV/slothlet/pull/937)), and in a browser work a finished run left behind keeps what it schedules, and any `run()` it opens, in the run ([#944](https://github.com/CLDMV/slothlet/pull/944)).
- Objects saved for an open run can be collected once the host drops them, closing a run no longer walks every saved object, and a deeply nested value handed out during a run is saved without a `RangeError` ([#938](https://github.com/CLDMV/slothlet/pull/938)).
- A run that writes metadata keeps a nested own `__proto__` key as an own key in its copy ([#930](https://github.com/CLDMV/slothlet/issues/930), [#937](https://github.com/CLDMV/slothlet/pull/937)).
- On the live runtime without `AsyncLocalStorage` (a browser), a second `reload()` or a `shutdown()` waits for a running `reload()` ([#929](https://github.com/CLDMV/slothlet/pull/929)).
- Api nodes and the framework namespace a module kept read nothing once their instance has shut down, and work an instance's modules left behind runs in no store after shutdown ([#915](https://github.com/CLDMV/slothlet/pull/915)).

### Loading, lazy mode and runtime

- Changes made through an unloaded lazy node are made on the node once it loads ([#653](https://github.com/CLDMV/slothlet/issues/653), [#706](https://github.com/CLDMV/slothlet/pull/706)).

- Three translations had dropped placeholders; they are restored ([#931](https://github.com/CLDMV/slothlet/issues/931), [#937](https://github.com/CLDMV/slothlet/pull/937)).
- Under vitest, module files load with `server.deps.inline` and no plugin ([#860](https://github.com/CLDMV/slothlet/pull/860), [#876](https://github.com/CLDMV/slothlet/pull/876)); outside vitest every compile under a loading file's name is that file's code.
- Reading an inherited method through a node no longer adds it to the node as an own member ([#913](https://github.com/CLDMV/slothlet/issues/913)), and a module's `self` on an object root reports the root's real prototype ([#914](https://github.com/CLDMV/slothlet/issues/914)).
- The `loader.materialize` callback gets the `materialized:complete` payload, `{ total, at }` ([#915](https://github.com/CLDMV/slothlet/pull/915)).
- `slothlet-migrate` reports the new `scope.isolation` default for configs that don't set it ([#915](https://github.com/CLDMV/slothlet/pull/915)).
- `diag.inspect().runtime.running` is `true` exactly while code of the instance (a call, a `run()` / `scope()` callback, a load) runs, on both runtimes ([#876](https://github.com/CLDMV/slothlet/pull/876)).

## ⚡ Performance

- Less per-call overhead on the wrapper's get and apply paths and in the async runtime's job hook ([#928](https://github.com/CLDMV/slothlet/pull/928)).
- A large value a module hands out again in a new run is no longer copied whole each time when it has not changed ([#938](https://github.com/CLDMV/slothlet/pull/938)).
- **v4 is slower than v3.** Against v3.24.0, measured with each version alone in its own 8-CPU container: creating an instance is 1.63x slower eager (18.0 ms → 29.4 ms) and 1.77x slower lazy (8.5 ms → 15.0 ms), shutdown is 1.89x / 2.23x slower (eager / lazy), and a call is 1.01x–1.61x slower (eager `math.add` 1.24x, 4.4 µs → 5.5 µs; realistic usage 1.61x eager, 1.48x lazy). The cost comes from keeping every run and call apart in every permission mode and from run snapshots. Full table, including v3.0.0, in [PERFORMANCE.md](../../PERFORMANCE.md#-v400-compared-with-v3240-and-v300).

## Upgrade notes

1. Read [docs/MIGRATION.md](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md).
2. Run `npx @cldmv/slothlet-migrate --write`, then `npx @cldmv/slothlet-migrate audit .` until it is clean. The audit also lists data keys (event, hook and error details) that no rewrite touches.
3. Check the behaviour changes by hand, since they keep their names: scoped `api.remove(apiPath, id)` order, routines now running and stacking by default, the copied init context, module-scoped privacy, and reported paths being segments arrays.
4. With permissions on: add `capability:*` rules for leaves that build code from strings, import `data:` / `blob:` URLs or register module hooks, and add the `@cldmv/slothlet/vite` plugin to vitest configs (forks pool).
5. For `permissions.mode: "strict"` on Node 22 with the async runtime, start Node with `--experimental-async-context-frame`. Under `"on"`, the same unmet check is a warning.
6. With permissions on, check modules that replace, redefine or delete members they may not read: those writes are now refused. A `:write` allow now grants the read too, a `:call` deny no longer stops a granted replacement, and a rule target with an unknown suffix is refused at startup. Metadata with a cycle through an array is refused too.
7. Expect a small cost on every promise step in the process while an instance exists (the async runtime's `async_hooks` hook, the live runtime's promise hooks); the [migration guide](https://github.com/CLDMV/slothlet/blob/master/docs/MIGRATION.md#process-wide-hooks-while-an-instance-exists) has the numbers.
8. Check code that relies on a `run()` / `scope()` seeing changes made after it started, or on its writes reaching the instance: a run now reads a snapshot as of its start. Built-ins read in a run are the run's copies, so compare them by content, not with `===`. Use `run.self()` or `scope({ self: true })` when the host's own changes in a run should stay in the run.
9. With permissions on, read members from `api` again after a `restart()`: code the replaced modules handed out before it is refused.
10. Match errors on `err.code`, not on message text (`FOLDER_INVALID` reads differently now).
11. Move code that imports a leaf file: reach the leaf through `self`, and put code two leaves share in a lib folder beside the api folder. This applies in every permission mode and to apis shipped as npm packages.
12. Uncaught exceptions: a host `uncaughtException` handler now gets every error, a `SlothletError` included, and the process keeps running if the handler lets it. Without a handler the process exits with code 1, not v3's 7, so update anything that checks for exit code 7.
13. Node floors are unchanged: `engines.node` `>=22.15.0` to run slothlet, `devEngines` `>=22.22.0` to develop it.
